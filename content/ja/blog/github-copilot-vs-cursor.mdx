## 正直に言うと、Cursorに驚きました

GitHub Copilotはリリース当初から使っていました。コーディングのスピードが明らかに上がって、もう手放せないツールになっていたんです。だからCursorが話題になった時も、「VS Codeのフォークでしょ？そこまで変わるの？」と思っていました。

でも実際に半年以上使ってみると、考えが変わりました。両方のツールにはっきりとした得意分野があって、単純に「どっちが上」とは言えないんです。具体的に比較していきます。

## 料金比較

まずはお金の話から。公式サイト基準の2026年後半時点の料金です。

| プラン | GitHub Copilot | Cursor |
|--------|---------------|--------|
| 無料プラン | 月2,000回のコード補完 | 月2,000回補完 + 50回プレミアムリクエスト |
| 個人向け | $10/月 (Individual) | $20/月 (Pro) |
| ビジネス | $19/月/人 (Business) | $40/月/人 (Business) |
| 学生・OSS | 無料 | 特別割引なし |
| モデル選択 | GPT-4o、Claude等 | GPT-4o、Claude、独自モデル等 |

価格面ではCopilotが圧倒的に有利です。特に学生やオープンソースコントリビューターなら無料で使えるのは大きいですね。Cursorは個人プランで月$20。倍の価格に見合う価値があるのか、以下で検証します。

## コード補完の品質

どちらもTabキーで候補を受け入れる基本的な操作は同じですが、体験はかなり違います。

**Copilot**は一行単位の補完がとにかく速くて正確です。タイピングの流れを邪魔せず、自然にTabを押してしまう感覚。VS Code以外にもJetBrains IDE、Neovimで使えるので、エディタを選ばないのも強みです。

**Cursor**のTab補完はもっとアグレッシブです。現在の行だけでなく、周囲のコードの文脈を広く読み取って、複数行をまとめて提案してくることが多いんです。最初は戸惑いますが、慣れると「自分がやろうとしていたことを正確に理解している」と感じる瞬間が増えます。

## チャット・エージェント機能

ここが両者の差が最も大きいポイントです。

Copilotのチャットはサイドバーでコードについて質問したり、説明を受けたり、簡単な修正を依頼するレベルです。2025年に追加されたAgent モードではターミナルコマンドの実行や複数ファイルの編集も可能になりました。ただ、CursorのComposerと比べるとまだ荒削りな印象です。

Cursorの**Composer**は正直、ゲームチェンジャーです。「このコンポーネントをリファクタリングして状態管理をzustandに変更して」と指示すると、関連する複数のファイルを同時に修正してくれます。各ファイルのdiffを確認しながら個別に適用できるので、制御を失う心配もありません。

プロジェクトを開くと自動的にコードベース全体をインデックスするので、文脈から外れた提案が少ないんです。`.cursorrules`ファイルをプロジェクトルートに置けば、コーディング規約やプロジェクト固有のルールをAIに認識させることもできます。

## コードベース認識能力

この点がCursorに高い評価を与える核心的な理由です。

| 機能 | GitHub Copilot | Cursor |
|------|---------------|--------|
| コードベースインデックス | 限定的 | プロジェクト全体を自動インデックス |
| マルチファイル編集 | Agentモードで対応 | Composerでネイティブ対応 |
| Diffプレビュー | 対応 | インラインdiff表示 |
| ロールバック | ファイル単位のundo | 変更セット単位のロールバック |
| ターミナル統合 | Agentがコマンド実行 | 内蔵AIターミナル |

Cursorは`@codebase`で「このプロジェクトの認証はどう処理されている？」と聞くと、関連ファイルを見つけて説明してくれます。Copilotも`#file`や`#codebase`タグでコンテキストを指定できますが、プロジェクト全体の理解度はCursorが一歩上です。

## メリット・デメリット

### GitHub Copilot

**メリット：**
- 月$10と手頃な価格設定
- 学生・OSSコントリビューター向け無料プラン
- VS Code、JetBrains、Neovimなど幅広いエディタ対応
- GitHub生態系との深い統合（PR要約、コードレビュー）
- 高速で邪魔にならないインライン補完

**デメリット：**
- コードベース全体の理解力がCursorに劣る
- マルチファイル編集はAgentモード限定
- チャットUIがCursorと比べてやや粗い

### Cursor

**メリット：**
- プロジェクト全体のインデックスによる高い文脈理解
- Composerによるシームレスなマルチファイル編集
- `.cursorrules`でプロジェクト別のAI動作をカスタマイズ可能
- AI前提で設計されたエディタ体験

**デメリット：**
- 月$20でCopilotの倍の価格
- VS Codeフォークのため他のエディタでは使用不可
- インデックス時にメモリを多く消費する場合がある
- VS Codeのアップデート反映がやや遅れることがある

## 結論：どちらを選ぶべきか

**Copilotがおすすめの方：**
- JetBrainsやNeovimなどVS Code以外のエディタを使いたい方
- 学生やオープンソース活動をされている方（無料）
- GitHubエコシステムをフル活用しているチーム
- コスパ重視で確実なAI支援が欲しい方

**Cursorがおすすめの方：**
- AIに指示してコードを書くスタイルが好きな方
- 大規模コードベースでのコンテキスト理解が重要な方
- リファクタリングやマルチファイル作業が頻繁な方
- VS Codeユーザーでエディタ変更に抵抗がない方

個人的には、会社のプロジェクトではCopilot Business、個人プロジェクトではCursorという使い分けをしています。一つだけ選ぶなら？正直、最近はCursor寄りです。Composerの体験とコードベース認識が生み出す「AIとの協働コーディング」は、プラグイン型のAI支援とは次元が違うと感じています。

ただし、月$10のCopilotのコスパの良さは否定できません。まずは両方の無料プランを試して、自分のワークフローに合う方を選ぶのがベストだと思います。
