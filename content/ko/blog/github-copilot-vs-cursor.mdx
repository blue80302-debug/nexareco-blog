## 솔직히 말하면, 둘 다 좋습니다

GitHub Copilot을 처음 쓰기 시작한 게 2023년이었고, Cursor는 2024년 중반부터 써봤습니다. 두 도구 모두 제 코딩 생산성을 확실히 올려줬는데, 방향이 좀 다릅니다. Copilot은 기존 워크플로우에 AI를 자연스럽게 끼워넣는 느낌이고, Cursor는 아예 AI를 중심에 놓고 에디터를 새로 만든 느낌이에요.

6개월 넘게 두 도구를 프로젝트마다 번갈아가며 써본 경험을 바탕으로, 어떤 상황에서 어떤 도구가 더 나은지 솔직하게 정리해봤습니다.

## 가격부터 비교하자

개발자에게 가격은 꽤 중요한 요소죠. 공식 사이트 기준으로 현재 가격은 이렇습니다.

| 항목 | GitHub Copilot | Cursor |
|------|---------------|--------|
| 무료 플랜 | 월 2,000회 코드 완성 제한 | 월 2,000회 완성 + 50회 프리미엄 요청 |
| 개인 유료 | $10/월 (Individual) | $20/월 (Pro) |
| 비즈니스 | $19/월/인 (Business) | $40/월/인 (Business) |
| 학생/OSS | 무료 | 별도 할인 없음 |
| 모델 선택 | GPT-4o, Claude 등 선택 가능 | GPT-4o, Claude, 자체 모델 등 |

Copilot이 가격 면에서는 확실히 유리합니다. 특히 학생이나 오픈소스 기여자라면 Copilot이 무료라는 게 큰 장점이에요. Cursor는 Pro 기준 월 $20인데, 그만한 값어치를 하는지는 아래에서 풀어보겠습니다.

## 코드 완성 품질

둘 다 탭 키 하나로 코드 제안을 받아들이는 건 같습니다. 하지만 체감 품질이 좀 다릅니다.

**Copilot**은 한 줄, 두 줄 단위의 코드 완성이 정말 빠르고 정확합니다. 타이핑하다가 자연스럽게 탭을 누르게 되는 경험이 잦아요. 특히 반복적인 패턴이나 보일러플레이트 코드에서 진가를 발휘합니다. VS Code뿐 아니라 JetBrains IDE, Neovim에서도 쓸 수 있어서 에디터를 가리지 않는 것도 장점이죠.

**Cursor**의 탭 완성은 좀 더 공격적입니다. 단순히 현재 줄만 보는 게 아니라, 주변 코드의 맥락을 더 넓게 읽어서 여러 줄을 한 번에 제안하는 경우가 많아요. 처음엔 좀 당황스러운데, 익숙해지면 "내가 뭘 하려는지 정확히 알고 있네" 싶은 순간이 옵니다.

## 채팅 및 에이전트 기능

여기서 두 도구의 격차가 벌어집니다.

Copilot의 채팅 기능은 사이드바에서 코드에 대해 질문하고, 설명을 받고, 간단한 수정을 요청하는 수준입니다. 2025년에 추가된 Agent 모드는 꽤 쓸만한데, 터미널 명령 실행이나 다중 파일 수정도 가능해졌어요. 다만 아직 Cursor의 Composer에 비하면 좀 투박한 느낌입니다.

Cursor의 **Composer**는 진짜 게임 체인저입니다. "이 컴포넌트를 리팩토링해서 상태 관리를 zustand로 바꿔줘"라고 하면, 관련된 파일 여러 개를 동시에 수정해줍니다. diff를 보여주면서 하나씩 적용할 수 있어서 제어권도 잃지 않고요. 프로젝트 전체를 인덱싱해서 코드베이스에 대한 이해도가 높다 보니, 맥락을 벗어나는 제안이 적습니다.

## 코드베이스 인식 능력

이 부분이 제가 Cursor에 점수를 더 주는 핵심 이유입니다.

Cursor는 프로젝트를 열면 자동으로 전체 코드베이스를 인덱싱합니다. 그래서 "@codebase 이 프로젝트에서 사용자 인증은 어떻게 처리하고 있어?"라고 물으면, 관련 파일들을 찾아서 설명해줍니다. `.cursorrules` 파일을 프로젝트 루트에 두면 코딩 컨벤션이나 프로젝트 규칙을 AI가 참고하게 할 수도 있어요.

Copilot도 `#file`이나 `#codebase` 같은 태그로 컨텍스트를 지정할 수 있지만, 전체적인 프로젝트 이해도는 Cursor가 한 수 위입니다.

## 멀티 파일 편집

실제 개발에서는 기능 하나 추가하려면 파일 5~6개를 동시에 건드려야 하는 경우가 많잖아요.

| 기능 | GitHub Copilot | Cursor |
|------|---------------|--------|
| 멀티 파일 수정 | Agent 모드에서 가능 | Composer로 자연스럽게 지원 |
| Diff 미리보기 | 지원 | 지원 (인라인 diff) |
| 되돌리기 | 파일별 undo | 변경 세트 단위 롤백 |
| 터미널 통합 | Agent 모드에서 명령 실행 | 내장 터미널에서 AI 명령 실행 |

Cursor의 Composer가 이 영역에서는 확실히 앞서 있습니다. 여러 파일에 걸친 변경을 하나의 "세션"으로 관리할 수 있고, 마음에 안 들면 통째로 되돌릴 수 있어요.

## 장단점 정리

### GitHub Copilot

**장점:**
- 가격이 저렴하고 학생/OSS 무료
- VS Code, JetBrains, Neovim 등 다양한 IDE 지원
- GitHub 생태계와 완벽한 통합 (PR 요약, 코드 리뷰 등)
- 빠르고 정확한 인라인 코드 완성

**단점:**
- 코드베이스 전체를 이해하는 능력이 상대적으로 부족
- 멀티 파일 편집이 Agent 모드에서만 가능
- 채팅 UX가 Cursor 대비 투박

### Cursor

**장점:**
- 코드베이스 인덱싱으로 프로젝트 맥락 이해도가 높음
- Composer를 통한 자연스러운 멀티 파일 편집
- `.cursorrules`로 프로젝트별 AI 행동 커스터마이징
- AI 네이티브 에디터라 전체적인 경험이 매끄러움

**단점:**
- 월 $20로 Copilot 대비 비쌈
- VS Code 포크라 다른 IDE 사용 불가
- 가끔 인덱싱이 느리거나 메모리를 많이 잡아먹음
- VS Code 업데이트 반영이 약간 느릴 수 있음

## 결론: 누가 뭘 써야 할까

**Copilot을 추천하는 경우:**
- JetBrains나 Neovim 등 VS Code 외 에디터를 주력으로 쓰는 분
- GitHub를 메인으로 쓰고 PR/이슈 통합이 중요한 팀
- 가격 대비 성능을 중시하는 분
- 학생이거나 오픈소스 프로젝트에 기여하는 분

**Cursor를 추천하는 경우:**
- "AI에게 지시해서 코딩하는" 스타일을 선호하는 분
- 대규모 코드베이스를 다루면서 AI의 맥락 이해가 중요한 분
- 리팩토링이나 멀티 파일 작업이 잦은 분
- VS Code를 주력으로 쓰고 에디터 변경에 거부감이 없는 분

저는 개인 프로젝트에서는 Cursor를 쓰고, 회사 업무에서는 Copilot Business를 씁니다. 둘 다 버리기 아까운 도구예요. 하지만 하나만 골라야 한다면? 솔직히 요즘은 Cursor 쪽으로 기울고 있습니다. AI 코딩의 미래가 "에디터 안의 플러그인"이 아니라 "AI를 중심에 둔 에디터"에 있다고 느끼거든요.
